# 最新帧处理线程设计

## 背景

当前 `two_stream` ROS 节点在 `YoloNode::syncImageCallback()` 内执行完整的
RGB/IR 图像处理流水线。节点使用 `ros::spin()`，因此同步回调在执行下列工作时，
会阻塞后续 ROS 回调的调度：

- ROS 图像转换、去畸变和 RGB 到 IR 图像配准；
- 双输入 YOLO 推理和检测后处理；
- RGB、IR 两路 SuperPoint 推理；
- LightGlue 匹配和极线约束过滤；
- 双目校正、三角测量、body 坐标系转换、目标位置聚合、可视化和结果发布。

单组图像的处理时间可能超过相机采集周期。本系统应优先保证目标定位结果的新鲜度，
而不是处理每一组历史图像。因此，需要将图像接收与处理解耦，同时避免产生无上限的
待处理图像积压。

## 目标

- 在上一组图像仍在处理时，保持 ROS RGB/IR 图像接收和时间同步回调可响应。
- 只保留一个待处理图像槽位；较新的同步图像对到达时，覆盖尚未开始处理的旧图像对。
- 使用一个独立处理线程执行当前的完整重处理流水线。
- 让检测器、TensorRT、特征提取、匹配、双目校正和目标聚合的可变状态全部归处理线程
  独占。
- 保持现有目标检测、双目几何、body 坐标系约定、阈值、标注图像话题和结果格式不变。
- 节点能够安全退出，不分离工作线程，也不强制中断正在执行的 CUDA 操作。

## 非目标

- 本次改动不把 YOLO、SuperPoint、LightGlue 或三角测量拆分成多个流水线阶段。
- 不让多组图像并发访问推理对象。
- 不切换到 `ros::AsyncSpinner` 或 `ros::MultiThreadedSpinner`。
- 不改变模型后端、模型输入、相机标定、坐标变换、检测阈值或 ROS 消息格式。
- 不保证每一组同步输入图像都会产生输出。

## 总体架构

应用层包含两个明确的线程：

```text
ROS 线程（`ros::spin()`）
  RGB 订阅器 + IR 订阅器
             |
  ApproximateTime 时间同步器
             |
  syncImageCallback(rgbMsg, irMsg)
             |
  覆盖单个待处理 FramePair
             |
       condition_variable
             v
独立处理线程
  取出待处理 FramePair 并清空槽位
             |
  processImagePair(rgbMsg, irMsg)
             |
  预处理 -> 推理 -> 匹配 -> 三角测量 -> 发布
```

ROS 回调是生产者，处理线程是唯一消费者。互斥锁只保护待处理槽位和停止状态。
消费者在执行任何图像转换或推理之前必须释放互斥锁。

## 图像所有权与最新帧策略

`FramePair` 保存同一组同步图像对应的两个只读指针：
`sensor_msgs::ImageConstPtr` 类型的 RGB 图像指针和 IR 图像指针。保留这些共享指针
可以延长底层 ROS 消息的生命周期，因此 ROS 回调不需要在入槽前进行图像转换或
深拷贝。

生产者执行流程：

1. 锁定待处理槽位的互斥锁。
2. 如果槽位中已经存在待处理图像对，使用新图像对覆盖它。
3. 如果槽位为空，将新图像对写入槽位。
4. 释放互斥锁并通知处理条件变量。

消费者执行流程：

1. 等待待处理图像对到达，或者等待节点发出停止请求。
2. 将待处理图像对移动到局部变量，并将共享槽位标记为空。
3. 释放互斥锁。
4. 将局部图像对完整处理结束。
5. 重复以上流程，并取出当时槽位中最新的图像对。

任何时刻最多只保留一组尚未开始处理的图像对。处理线程已经取走的图像对允许执行
完成；当更新的图像对到达时，不取消正在进行的推理。这既限制了排队延迟，也避免了
不安全地中断推理过程。

## 处理线程所有权与数据流

将当前 `syncImageCallback()` 中的重处理逻辑迁移到 `processImagePair()`。
新的 `syncImageCallback()` 只负责更新最新帧槽位。

下列对象和状态只允许处理线程访问：

- `YoloDetector` 及其 ONNX Runtime 或 TensorRT 状态；
- SuperPoint、LightGlue 对象及其 TensorRT 执行上下文；
- `feature_points0`、`feature_points1`、特征分数和匹配结果；
- 双目校正就绪状态、图像尺寸、校正矩阵和三角测量成员；
- 每组图像对应的检测、三角测量、目标聚合、可视化和发布操作。

相机标定参数和固定坐标变换必须在线程启动前完成初始化。推理对象不会被多个线程
并发访问，因此不需要为现有同步推理接口额外增加推理锁或创建更多执行上下文。

标注图像由处理线程发布。当 `show_window` 启用时，所有 OpenCV HighGUI 操作也应在
处理线程中执行，避免 ROS 接收线程和处理线程并发访问 GUI 状态。

## 生命周期与退出

节点构造顺序：

1. 读取 ROS 参数和配置文件。
2. 加载相机标定参数并计算固定几何关系。
3. 初始化 YOLO、SuperPoint 和 LightGlue。
4. 注册 RGB/IR 订阅器和同步回调。
5. 最后启动处理线程；此时 `main()` 尚未进入 `ros::spin()`，不会有回调并发进入。

节点析构顺序：

1. 停止或取消 RGB/IR 图像订阅，保证不再产生新的同步图像对。
2. 在待处理槽位互斥锁保护下设置停止状态，并丢弃尚未开始处理的图像对。
3. 通知处理条件变量。
4. 如果处理线程可连接，则调用 `join()` 等待其退出。

如果处理线程已经开始处理一组图像，节点析构会等待这组图像处理完成。本设计不强制
终止线程，也不中断正在执行的 ONNX Runtime、TensorRT 或 CUDA 调用。

## 异常处理

配置或模型初始化失败仍然是致命错误，继续按照当前逻辑从节点构造函数向外抛出。

处理循环在每次调用 `processImagePair()` 的外层设置统一异常边界：

- 捕获 `cv_bridge::Exception` 和 `cv::Exception`，记录错误并只丢弃当前图像对；
- 捕获其他 `std::exception`，记录错误并只丢弃当前图像对；
- 如果没有收到停止请求，处理循环继续等待或获取下一组最新图像。

任何异常都不能越过处理线程入口函数。`std::thread` 中未捕获的异常会导致整个进程
终止。对于连续重复出现的错误，可采用节流错误日志，避免 ROS 控制台被同类异常刷屏。

## 测试方案

为最新帧交接机制增加不依赖模型加载的独立测试：

1. 在消费者取出之前依次写入图像对 A、B，消费者必须得到 B。
2. 消费者处于等待状态时，写入新图像对能够正确唤醒消费者。
3. 发出停止请求能够唤醒等待中的消费者，并使其在没有图像的情况下退出。
4. 消费者取走一组图像后，生产者可以在该图像处理期间继续写入并覆盖共享槽位。
5. 节点退出时丢弃尚未开始处理的图像对，并安全连接处理线程。

继续运行现有检测解码/后处理、相机几何和配置读取测试，确认移动处理流水线没有改变
数值行为。

运行时使用高于节点处理能力的输入帧率进行验证，并检查：

- 处理线程工作期间，ROS 接收回调仍然能够持续接收同步图像对；
- 待处理槽位始终限制为一组图像，不形成不断增长的输入积压；
- 输出时间戳持续接近较新的输入时间戳，不会产生不断增长的延迟；
- 节点在处理线程空闲和正在处理图像时均能安全退出；
- 标注图像和 body 坐标系下的三维定位结果保持现有语义。

## 风险与应对措施

- **对象析构后访问：** 先停止订阅，再请求工作线程退出，并在线程完成后才销毁节点
  成员。
- **推理数据竞争：** 所有推理对象和每帧可变状态均由唯一处理线程独占。
- **锁竞争：** 图像转换、推理、几何计算、可视化和发布期间不得持有待处理槽位锁。
- **输出过旧：** 待处理容量固定为一组；每次收到更新的同步图像对时覆盖尚未处理的
  旧图像对。
- **进程意外终止：** 在工作线程边界捕获每帧处理异常。
- **GUI 并发访问：** 所有 HighGUI 调用集中在处理线程。

## 验收标准

- 处理线程正在处理一组图像时，ROS 同步回调仍能接收并替换待处理图像对。
- 最多只保留一组尚未开始处理的 RGB/IR 图像对。
- 推理和几何流水线不会同时处理两组图像。
- 每组图像处理完成后，下一次选择的是当时最新的待处理图像对。
- 节点退出时不存在分离线程、死锁或未捕获的工作线程异常。
- 现有目标检测和 body 坐标系三维定位行为保持不变。
